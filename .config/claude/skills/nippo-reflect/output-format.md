# 追記フォーマット

**日報ファイルの末尾に追記する。** 「💡 学び・気づき」の直後に挟まない。

`/nippo-finalize` は 💡 学び・気づき → 📋 日次チェックポイント → ⚠️ 宣言と実績のズレ →
🚀 着手候補リスト を**一体のレポートとして**出す。その途中に割り込むと finalize の成果物が
分断されるうえ、見出しレベルを周囲に合わせて下げることになり、別パスの出力なのに
finalize の子セクションに見えてしまう。

**見出しは `##` で始める。** 周囲に合わせて `###` へ下げない。finalize と対等な、
独立した1パスの出力であることを構造で示す。

**空欄（`- A:` の後ろ、`**あなたの行動仮説**:` の後ろ）はすべて空のまま出力する。** AIが埋めない。

```markdown
---

## 🔍 今日の振り返り（/nippo-reflect）

**振り返る行為**: [作業ログから抽出した具体的行為を1文で]
**なぜこれか**: [判断が分かれた点／想定とズレた点を1文で]

### 1. 行為（何をしたか）

[作業ログから事実だけを客観的に再構成する。評価を混ぜない]

### 2. 振り返り（何が起きていたか）

- Q: [その場面の具体に紐づく問い]
  - A:
- Q: [その場面の具体に紐づく問い]
  - A:

### 3. 本質的な気づき（何が要点か）

> パターンや深層の要因に目を向けてみてください

- Q: [具体的エピソードに基づく問い]
  - A:

📎 参考: [関連する原則やメンタルモデル。無ければこの行ごと省く]

### 4. 代替案（他にどうできたか）

- Q: [別の可能性を探る問い]
  - A:

### 5. 試行（次にどうするか）

> 以下は候補です。何をやるかはあなたが決めてください

**候補**:

1. [次に試せるアプローチ]
2. [次に試せるアプローチ]

**あなたの行動仮説**:

### 👀 別の視点から

> その行為に対して最も異なる見方をする1〜2視点だけ。3視点を機械的に並べない

- **[視点名]**
  - 観察: [作業ログから観察した点]
  - 問いかけ: [その視点から立つ問い]
  - A:
```

## 視点の選び方

| 視点               | 見るもの                             |
| ------------------ | ------------------------------------ |
| シニアエンジニア   | 判断の質                             |
| スタッフエンジニア | システム全体との整合性               |
| ビジネスサイド     | 成果の定量化可能性・ビジネスインパクト |

選んだ行為に対して**最も異なる角度から光が当たる**ものを1〜2個選ぶ。
全部並べると、どの指摘も薄くなって読まれない。
