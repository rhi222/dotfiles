# 面談・面接の準備タスクを起票する

新規日報ファイル作成時に、面談・面接の予定を拾って準備タスクを Linear へ起票し、
日報の `## 面談準備` セクションに結果を書くためのロジック。

**起票はスクリプトに任せる。** 判断（どれが面談か・準備に何が要るか）だけをここで行い、
重複チェック・起票・seen 追記は `scripts/linear-interview-prep.sh` が担う。
`linear-slack-sweep` と同じ役割分担。

## 対象にする予定

`calendar-schedule.md` で取得した予定のうち、次を**すべて**満たすもの。

- タイトルに `面談` または `面接` を含む
- 自分（`self: true`）が参加予定
- キャンセル（`status: cancelled`）でない / 自分が辞退（`responseStatus: declined`）でない
- 当日中止が明記されていない

**キーワードは `面談` / `面接` の2語だけにする。** 実データではカジュアル面談・オファー面談・
採用チャネル経由の面談・業務委託の面談・社内の配属面談が、すべてこの2語のどちらかを含む。
チャネル名や社名で条件を足すと、名前が変わるたびに漏れるうえ、このリポジトリは public なので
社内固有の語を置けない。

**`1on1` は対象外。** 定例で毎週あり、準備タスクが毎週積まれると Linear が汚れる。

## 対象にする日

**当日と翌営業日の2日分。** 翌日分を含めるのは、候補者の経歴を読むような準備を
前日の空き時間に仕込みたいため。金曜に作成した場合の「翌営業日」は月曜。

取得は `mcp__claude_ai_Google_Calendar__list_events` を2回呼ぶか、
`startTime` を当日 `00:00:00`、`endTime` を翌営業日 `23:59:59` にして1回で取る。

**同じ予定を前日と当日で必ず2回拾う。** 二重起票を防ぐのはスクリプト側の責務なので、
ここでは重複を気にせず全部渡してよい。

## 準備タスクの組み立て

予定の `description` と `attachments` から材料を拾って個別化する。
**材料があるのに定型文で埋めない。** 準備の価値はここにしかない。

| 材料 | 準備タスクにどう変えるか |
| --- | --- |
| 候補者からの質問（「特に訊いてみたいこと」等） | 質問ごとに「〜への回答を用意する」を1件立てる |
| 添付のスキルシート / 職務経歴書 PDF | 「スキルシートを読み、確認したい点を3つ決める」 |
| 面談メモ・議事録のリンク | 「前回の面談メモを読み直す」 |
| 外部サービスの候補者ID | 「プロフィールを事前に確認する」 |
| 同席者が居る | 「同席者と役割分担を確認する」 |

材料が何も無い場合だけ、次の定型に落とす。

```markdown
- [ ] 経歴と志望動機を確認する
- [ ] 事業・組織の説明を直近の内容に揃える
- [ ] 逆質問への回答を用意する
```

## 起票する

### 1. 未起票のものだけに絞る

```bash
SCRIPT="$(ghq root)/github.com/rhi222/dotfiles/scripts/linear-interview-prep.sh"
bash "$SCRIPT" unseen <event_id>...
```

返ってきた event id のものだけを次へ進める。

### 2. 起票する

event id ごとに1回ずつ呼ぶ。

```bash
bash "$SCRIPT" create <event_id> <title> <when> <event_url> <prep> [label...]
```

| 引数 | 中身 |
| --- | --- |
| `event_id` | カレンダーの `id`（重複判定のキー） |
| `title` | `面談準備: <相手が分かる短い名前> (MM/DD HH:MM)` |
| `when` | `YYYY-MM-DD HH:MM` |
| `event_url` | 予定の `htmlLink` |
| `prep` | 上で組み立てたチェックリスト（markdown） |
| `label` | `role:*` / `em:*` を推定して渡す。通常は `role:manager` と `em:people` |

`src:mtg` はスクリプトが固定で付けるので渡さない。state は `Todo` 固定。

出力は `created NSY-xx` / `skipped(seen) <id>` / `skipped(exists) NSY-xx` のいずれか。

Linear にアクセスできない場合（config 未生成・オフライン）は**起票をスキップして日報作成を続行する**。
日報の作成自体を止めない。その場合は日報に準備チェックリストだけ書く。

## 日報への書き方

`## 今日の予定` の直後に `## 面談準備` を置く。翌日分は別見出しで分ける。

```markdown
## 面談準備

### today 18:00 カジュアル面談（候補者A） — NSY-201

- [ ] スキルシートを読み、確認したい点を3つ決める
- [ ] 「リファクタリングの検討背景」への回答を用意する

### 翌営業日 10:00 面接（候補者B） — NSY-202

- [ ] 経歴と志望動機を確認する
```

- 起票できたら見出し末尾に issue の identifier を付ける
- `skipped(exists)` のときも既存の identifier を付ける（同じ準備を二度書かないため）
- 対象の予定が1件も無ければ、このセクションごと出さない

**候補者の実名・メールアドレスは日報と Linear にだけ書く。**
どちらもローカルと個人のタスク管理で、チームの共有物ではない。
