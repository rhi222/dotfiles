# SoS 事前記載確認スレの草稿を作る

毎週の定例（金15:00）の前に、確認スレへ「今週のdiff URL一覧」と「まだ書けていない人への
メンション」を投げる。その文面を組み立てる。

引数: $ARGUMENTS
形式: `[YYYY-MM-DD]`（省略時は今日。過去日を渡すとその週として判定する）

**Slackへは投稿しない。草稿を会話に出すところまでで終わる。** 催促は名指しで人に届くので、
送るかどうか・誰を外すか（休み、代打、既に別経路で連絡済み）は人が決める領域にある。
Slackへ書き込めるツールはこのskillに許可していない。

## 判定はスクリプトに任せる

```bash
bash "$(ghq root)/github.com/rhi222/dotfiles/scripts/esa/sos-precheck.sh" check [YYYY-MM-DD]
```

cwd 相対では書かない（どのリポジトリで作業中でも呼べるようにする）。

返るのは設定の並び順どおりのJSON配列。1件は次の形。

| キー                    | 意味                                           |
| ----------------------- | ---------------------------------------------- |
| `post_number`           | esa記事番号。週次議事録が未作成の週だけ `null` |
| `label`                 | 領域名（検索 / 予約 など）                     |
| `owner` / `slack_id`    | 未更新のときにメンションする相手               |
| `updated`               | 前回SoS以降にリビジョンが増えたか              |
| `from_rev` / `head_rev` | 判定に使ったリビジョン番号                     |
| `url`                   | スレに貼るURL（後述の3種を出し分け済み）       |
| `mention`               | この記事でメンションすべきか                   |

**URLの出し分けはスクリプト側で閉じている。** 手で組み立て直さないこと。

| 状態                       | URL                                                     |
| -------------------------- | ------------------------------------------------------- |
| 更新あり                   | `.../posts/N/revisions/compare/<from>...head/html_diff` |
| 更新なし                   | `.../posts/N/revisions`                                 |
| `link_style: plain` の記事 | `.../posts/N`                                           |

TOを `head` で固定しているのは、投稿してから定例までの間に追記されてもURLを貼り直さずに
最新差分が出るため。

## 手順

### 1. 判定を実行する

上のコマンドを1回呼ぶ。`ESA_ACCESS_TOKEN` 未設定・設定ファイル不在なら
スクリプトが落ちるので、そのまま利用者に伝えて終了する（推測で埋めない）。

### 2. 草稿を組み立てる

```
--- YYYY/MM/DD ---
```

<url を設定の並び順で1行ずつ>

```
@owner @owner esaの更新お願いします。
```

- 日付は**今回の定例の金曜日**（実行日ではない）
- URLはコードブロックで囲む。囲まないとSlackがOGP展開して縦に伸び、一覧として読めなくなる
- メンション行は `mention: true` の `owner` を `@owner` の形で並べる。`updated: true` の人は
  入れない
- **`<@U...>` のID表記では書かない。** 草稿は人が読んで送るもので、IDのままでは誰を
  呼んでいるか目視で確認できず、誤メンションがそのまま通る。`slack_id` はJSONには入って
  いるが、草稿には出さない
- **同じ相手は1回だけ書く。** 1人が複数の記事を持つ設定になっているので、素直に並べると
  同じ人を2回呼ぶ。並び順は設定の並び順（初出の位置）を保つ
- **`mention: true` が0件なら、メンション行を「皆さん記載ありがとうございます :peko_kuma:」に置き換える。**
  誰も催促しない週に空のメンション行を残さない

### 3. 例外を明示する

草稿の外（会話側）に、次に当てはまるものだけ1行で添える。**草稿の中には入れない**（そのまま
貼れる状態を保つため）。

- `post_number` が `null` の記事 → 「週次議事録が未作成。URLは手で足すか、作成を依頼する」
- `owner` が空のまま未更新だった記事 → 「宛先未設定なので黙っている。設定JSONに足すか？」

### 4. 判定の内訳を出す

草稿の後に、確認用の表を出す。

| 領域 | 判定     | rev       | メンション |
| ---- | -------- | --------- | ---------- |
| 検索 | 更新あり | 172 → 178 | —          |
| 予約 | 未更新   | 176 → 176 | @owner     |

**これを出すのは、誤メンションにその場で気づけるようにするため。** 草稿だけ見せると
「なぜこの人が入っているのか」が確認できず、送ってから気づくことになる。

## 設定

`sos-precheck-posts.json`（このskillの隣。実体は private bundle 側にあり symlink で入る）。

```json
{
  "team": "<esa team>",
  "posts": [
    {
      "post_number": 0,
      "label": "領域名",
      "owner": "screen_name",
      "slack_id": "U..."
    },
    {
      "post_number": 0,
      "label": "メンション不要な記事",
      "mention": false,
      "link_style": "plain"
    },
    {
      "dynamic": "weekly_minutes",
      "label": "週次議事録",
      "category": "<esaのカテゴリ>",
      "mention": false,
      "link_style": "plain"
    }
  ]
}
```

- **配列の順序がそのまま草稿の行順になる。** スレの見た目を週ごとに揺らさないため、
  並べ替えるときは設定側を直す
- `mention` 省略時は `true`
- `dynamic: weekly_minutes` は毎週新しい記事が立つものを指す。`<category>/<YYYYMMDD>`（今回の
  金曜日付）で引くので番号を固定しない

## 判定の境界

- 起点は**前週金曜15:00**。実行日が木でも金の午前でも同じ週を指す
- FROMは「前週金15:00 **より前**の最新リビジョン」。金15:00ちょうど以降は前回の定例に
  映っていないので、今週の差分に含める
- リビジョンは新しい順に100件ずつ返るので、基準より古いものが出るまでページを辿る

いずれも `tests/esa/test-sos-precheck.sh` で固定してある。挙動を変えるときはテストを先に直す。

## やらないこと

- **Slackへの書き込み**（投稿・返信・スタンプ）
- **diffの中身の要約。** ここは「書けているか / 書けていないか」だけを見る。中身の要約は
  `esa-weekly-report` の担当で、読む相手も目的も違う
- **メンション相手の取捨選択。** 休み・代打・連絡済みはスレの外の情報なので、
  草稿にそのまま出して人に判断させる
