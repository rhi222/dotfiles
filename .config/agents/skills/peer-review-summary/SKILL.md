# Peer Review Summary

複数人の自由記述を、少数意見を消さず、意見の多さを回答者数で示して集約する。
詳細要約では原文を追跡可能にし、共有用テキストでは個々の原文を出さない。

## 事前確認

1. 対象ファイルと同じディレクトリの既存ノートを確認し、見出し、文体、リンク形式を合わせる。
2. 原文の区切りと回答者数を確定する。箇条書きが1回答内に複数あっても、別回答者として数えない。
3. 良い点と改善・期待が同じ順序の回答者に対応するか確認する。
   ユーザーの説明や入力形式から対応が確定している場合だけ、同じ番号を同一回答者として扱う。
4. 対応関係、回答境界、共有範囲が結果を変えるのに確定できない場合だけ、ユーザーへ短く確認する。

## 原文へのID付与

- 良い点は `G-1`、`G-2`、改善・期待は `I-1`、`I-2` のように採番する。
- 良い点と改善・期待が同一回答者に対応する場合は、同じ末尾番号を使う。
- 各IDを回答の直前へ置き、原文の語句、誤字、改行、箇条書きは変更しない。
- 原文を削除、要約、並べ替えない。既存の要約がある場合は重複追加せず更新する。

## 集約

良い点と改善・期待を、それぞれ3〜5個の観点へまとめる。

- 一般論ではなく、原文にある行動、対象、案件、判断に基づいて観点名を付ける。
- 1回答が複数観点に触れていれば重複して分類してよい。
- 各観点の人数は、言及数ではなく異なる回答者数を数える。同一回答者が同じ観点を複数回述べても1名とする。
- 件数の多い観点から並べる。ただし少数でも安全、健康、重大な対人課題は落とさない。
- 「全員」「多く」などの曖昧な表現だけで済ませず、人数を示す。
- 決まっていないことや推測を、事実として補わない。

## 詳細要約

原文の後ろへ、次の順序で追記する。

```markdown
# 要約

## 集計方法

- 回答者数とIDの規則
- 複数観点への重複集計であること

## 良い点

### 1. 観点名（9名）

要約文。

- 該当: G-1、G-3、G-7
- 原文の手がかり: 「短い語句」「短い語句」

## 改善してほしい点・期待している点

### 1. 観点名（7名）

要約文。

- 該当: I-1、I-5、I-8
- 原文の手がかり: 「短い語句」「短い語句」
```

「原文の手がかり」は照合の入口になる短い語句だけにする。原文全体を複製しない。

## 共有用テキスト

詳細要約の下へ、通常の入れ子付き箇条書きで追加する。

```markdown
## 共有用テキスト

- 前提
  - N名からのフィードバック
  - 1名が複数の観点に触れた場合は重複して集計
- 評価できる点
  - 複数領域への理解と判断力が評価されている（9名）
- 期待している点・改善してほしい点
  - 判断基準や権限も含めた育成が期待されている（7名）
```

共有用テキストでは次を守る。

- 原文、引用、G/Iの参照IDを載せない。
- 人数は文末の全角括弧で `（N名）` と書く。
- 詳細要約の全観点を省略せず、一対一で転記する。
- ユーザーが追記した前提や表現は保持する。
- 回答者の所属や関係性は、原文またはユーザーの説明にある場合だけ書く。

## 前回peer reviewとの差分

前回のpeer reviewがある場合は、現在の要約の後ろに比較を追加する。
ユーザーが差分だけを依頼した場合は、既存の要約を作り直さず比較部分だけを追加または更新する。

### 比較前の確認

1. 両方の評価時点、回答者数、対象者の範囲、資料の粒度を確認する。
2. 前回が集約済みサマリ、今回が原文付き集計など、資料の粒度が違う場合は冒頭に明記する。
3. 母集団や集計方法が違う場合、人数の増減を直接比較しない。テーマの継続、具体化、役割の広がりを比較する。
4. 今回言及されなかったテーマを、改善済み・解消済みとは判断しない。単に確認できない可能性を残す。

### 詳細比較

双方の表現を次のような共通観点へ対応付ける。

- 強みの継続または対象範囲の拡大
- 以前の期待が今回の評価として現れた点
- 継続している課題と、具体化した改善対象
- 今回初めて現れた論点
- 根拠不足で変化を判定できない点

比較結果は、根拠を追える表と、本人の変化を表す短い箇条書きにする。

```markdown
### 今回とのdiff

比較可能性についての注記。

| 観点   | 前回       | 今回       | 差分                       |
| ------ | ---------- | ---------- | -------------------------- |
| 観点名 | 前回の要約 | 今回の要約 | 継続・具体化・変化と参照ID |

### そこから見えてくる本人の変化

- 根拠から読み取れる役割や行動の変化
- 継続している課題と、次に期待される変化
```

本人の変化は、評価内容から説明できる範囲に限定する。
「期待された」ことと「できるようになった」ことを区別し、期待だけを成長の実績として扱わない。

### diffの共有用テキスト

詳細比較の後ろに、共有用の通常の入れ子付き箇条書きを追加する。

```markdown
### diffの共有用テキスト

- 前提
  - 資料の粒度や母集団が異なる場合の注意
- 継続・伸長している点
  - 前回から続く強みや、対象範囲が広がった点
- 次の課題として明確になった点
  - 継続課題と、今回具体化した改善対象
- 本人の変化
  - 役割や行動の変化と次の段階
```

diffの共有用テキストにも原文、引用、G/Iの参照IDを載せない。
詳細比較で扱った重要な差分と本人の変化を省略せず、短く言い換える。

## 確認

編集後に次を確認する。

1. G/IのID数が回答者数と一致している。
2. 同じ末尾番号が同一回答者を指している、または対応関係を主張していない。
3. 各観点の人数と該当ID数が一致し、同一回答者を二重に数えていない。
4. 詳細要約の全観点が共有用テキストにもある。
5. 共有用テキストに引用や参照IDがない。
6. 前回との差分がある場合、資料の粒度と母集団の違いを踏まえて比較している。
7. 言及がないことを改善済みと断定せず、期待と実績を区別している。
8. 詳細比較の重要な内容がdiffの共有用テキストにもある。
9. 対象ファイル以外を変更していない。

変更後は `git diff -- <対象ファイル>` で差分を確認する。対象が未追跡なら、該当範囲を読み直して確認する。
