# glossary

社内用語辞書 `glossary.md` を読んで用語の意味とコード上の起点を答え、
新しく分かった用語を同じ書式で追記する。

## 辞書の所在

このskillと同じディレクトリの `glossary.md`。**社内固有の値なので gitignore されており、
実体は `~/.local/share/dotfiles-private/` にある**（dotfilesは public）。
書式は隣の `glossary.md.example` を見る。

`glossary.md` が無い、または用語が載っていないときは**推測せず利用者に確認する**。
知らない用語を一般的な意味で解釈して調査を始めない。

## 引く

1. `glossary.md` を Read し、見出し（`## 用語`）と `別名:` の両方から探す。表記ゆれ
   （大文字小文字、全角半角、連携/連係）は寄せて照合する
2. 見つかったら `意味` を答え、`起点` があれば調査・実装はそこから読み始める
3. `起点` のリポジトリは `cross-repo-investigate/repos.yml` のエイリアスで書かれている。
   cross-repo-investigate と同じ方法で `path` に解決してから相対pathを結合する
4. 複数の用語を同時に聞かれたら1回のReadでまとめて答える

## 追記する

「辞書に追加して」「用語を登録して」と言われたとき、または調査で用語の意味と起点が
確定して利用者が記録を求めたときに `glossary.md` の末尾へ追記する。

- 書式は `glossary.md.example` の1エントリと同じ。項目名を変えたり増やしたりしない
- 意味は会話で確定した内容だけを書く。推測で補完しない
- 同じ用語の見出しが既にあれば新規追加せず、その節を更新する
- 起点のリポジトリは絶対pathでなく repos.yml のエイリアスで書く。エイリアスが無ければ
  利用者に確認する

## 書き方の例

```markdown
## dive連携

- 意味: 予約記録を夜間に外部へ渡すバッチ処理
- 別名: dive, ダイブ連携
- 起点: `予約` / `batch/dive/main.go`
- 関連: sample-record-api
```

`起点` は `<repos.ymlエイリアス> / <リポジトリ内相対path>`。1行に1つ。複数あれば行を増やす。
