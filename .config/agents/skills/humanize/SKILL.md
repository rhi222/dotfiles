文章からAI特有のパターンを検出・修正し、人間が書いたような自然な文章に変換するスキルです。

## 使い方

### ケース1: ユーザーが文章を渡す場合

ユーザーが「この文章をhumanizeして」と文章を渡してきた場合、その文章に対して2パス処理を実行します。

### ケース2: 自己修正

agentが生成した文章に対して「AIっぽいのを直して」と言われた場合、直前の出力に対して2パス処理を実行します。

## 処理フロー（2パス）

### Pass 1: パターン検出

文章を修正せず、以下のパターン一覧に基づいて問題箇所を特定します。

- 該当パターンのIDと箇所を列挙する
- 検出されなかったカテゴリは省略する

### Pass 2: 修正実施

検出結果に基づいて文章を修正し、出力フォーマットに従って結果を返します。

- 修正は最小限にとどめ、元の意味を変えない
- 文章全体のトーンと文脈を考慮する
- 一度に全パターンを直すのではなく、不自然さが大きいものから優先する

### 候補語の確認方法

Pass 1 では、B6〜B8 に挙げた語がないか先に検索する。見つけた語を機械的に置換せず、文ごとに次を確認する。

- 読者がその語だけで、対象、操作、順序、完了条件を特定できるか
- その分野で意味が定まった用語か。たとえば「CI パイプライン」「データ構造」は、それぞれ固有の対象を指すなら残す
- 比喩を外して「何をどうするか」を書いたほうが短く明確にならないか
- 「唯一」などの断定には、範囲と根拠が文中または参照先にあるか

同じ候補語が複数回出る場合は、文書全体を検索して一括で確認する。ただし、置換結果は文脈ごとに決める。

## 「魂のある文章」への転換ガイド

パターン除去だけでは平板な文章になる。以下の観点で能動的に改善する。

### 意見を持つ

曖昧なヘッジを削り、筆者の立場を明確にする。「〜と言えるかもしれません」→「〜だ」。ただし根拠がない断言は避ける。

### リズムを崩す

短文と長文を混ぜる。すべて同じ長さの文が並ぶとAI感が増す。体言止めや倒置も有効。

### 具体的に書く

「さまざまな」「多くの」を具体例に置き換える。「さまざまなメリットがあります」→「読み込み速度が3倍になる」。

抽象ジャーゴン（B6）も同じで、「3層構造」「レイヤー」と書きたくなったら、その場で扱っている実装名に置き換えられないか考える。「3層構造」→「画面・処理・DB」「Reactコンポーネント／APIサーバ／PostgreSQL」。「判断する」→「決める/選ぶ/やる」。「フロー」→「手順/流れ」。ジャーゴンが本当に必要なのは、その語自体が固有の概念を指している場合（OSI参照モデルの「レイヤー」など）だけだ。

大仰な比喩・キメ語（B7）も同様に平易な語へ。「本丸」→「中核/中心/要」、「品質ゲート」→「品質チェック/歯止め」、「突合ゲート」→「突合チェック/突合する仕組み」、「判定ゲート」→「判定」、「肝/キモ」→「要点」、「ボトルネック」→「詰まり/律速」、「二段構え/三段構え」→具体的な順序で書く（「まずA、次にB」）、「両輪」→「AとBの両方」。比喩やキメ表現を使うと一見締まって見えるが、AIが多用する手癖でもある。具体的な動作・対象・順序に置き換えられるなら置き換える。

説明を省く比喩（B8）は、単語だけを平易な類義語へ置き換えるのではなく、省かれている内容を補う。「作業を3つの帯で読む」→「作業を目的別に3つに分ける」、「テストをP8に寄せる」→「テストをP8でまとめて実施する」、「Unitテストを各フェーズに同梱する」→「各フェーズでUnitテストも実装する」、「機能を一周させる」→「各機能を連携させ、一連の動作を確認する」、「確認の窓を広げる」→「確認するファイルと期間を増やす」。同じように、「正本」は何を正式な記録とするのか、「入口」「出口」は開始条件と完了条件のどちらかを具体的に書く。「窓」は、確認範囲、受付期間、時間帯など、文脈に応じた具体的な対象へ置き換える。ただし、UIのウィンドウや窓関数など、その分野で意味が定まった用語は残す。

## 出力フォーマット

```
[修正後の文章をここに出力]

---
**修正サマリー**
- [パターンID] 修正内容の簡潔な説明
- [パターンID] 修正内容の簡潔な説明
```

例:

```
---
**修正サマリー**
- [A1] 「革命的な変化」→「大きな変化」に変更
- [B1] 段落冒頭の「さらに」「加えて」の連続を解消
- [D1] 「参考になれば幸いです」を削除
```

## 注意事項

- **文脈判断**: ビジネスメールの敬語（「何卒よろしくお願いいたします」等）は日本語の文化的慣習であり、AIくささではない。修正対象外とする
- **技術的正確性**: 修正によって技術的な正確性が損なわれないようにする
- **意味の保持**: 元の文章の主張・意図を変えない。表現を変えるだけにとどめる
- **過剰修正の防止**: すべてのパターンを機械的に除去するのではなく、文脈に応じて判断する。「さらに」が1回だけ使われている場合は問題ない
- **文体の一貫性**: 修正後の文章内でです・ます調と、だ・である調が混在しないようにする
