# 用語の選び方

## 読み手ごとの基準

| 読み手             | 使ってよい語                       | 避ける語                                 |
| ------------------ | ---------------------------------- | ---------------------------------------- |
| 社内エンジニア     | 用語表で定義した略語、コード名     | 用語表に無い略語                         |
| 社内の非エンジニア | 業務の言葉、役割を添えたシステム名 | コード名、内部の処理名                   |
| 顧客・他社         | 顧客の業務の言葉                   | 社内略語、コード名、repo名、社内の部署名 |

## 抽象語

次の語は、中身を言わずに使うと「何も言っていない」文になる。
使う場合は、直後に「誰が・何を・どうするか」を書く。書けないなら語ごと消す。

- 仕組み化、再利用、最適化、効率化、可視化、標準化
- 横断、連携強化、構造課題、全体最適、底上げ
- 推進、整備、強化、検討を進める

| 悪い例                   | 良い例                                                                |
| ------------------------ | --------------------------------------------------------------------- |
| 判断を仕組みで再利用する | 過去の承認理由をチケットに残し、同じ種類の依頼は担当者が1人で承認する |
| 構造課題を解消する       | 変更のたびに3チームの承認が要る状態をやめ、承認者を1人にする          |
| 連携を強化する           | 毎週の定例で在庫の差分を確認する                                      |

## 平易な言い換え

内部で生まれた造語は、読み手が初めて見る語なら一般的な言葉に言い換える。

| 内部の造語   | 言い換え                 |
| ------------ | ------------------------ |
| 越境アクセス | 権限外のアクセス         |
| 在庫引当     | 在庫の確保               |
| 突合         | 照らし合わせ（顧客向け） |

## 表記の統一

- 同じものを指す語は1つに決め、用語表に載せる。章ごとに言い換えない
- 図・表・本文・見出しで同じ表記を使う
- 本文に出てこない語を、図や見出しや要約に初登場させない
